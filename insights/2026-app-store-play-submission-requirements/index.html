2026년 앱 스토어 제출 요건 정리 — 지금 업데이트가 막히는 이유

2026년에 App Store와 Google Play의 제출 요건이 모두 바뀌었습니다. Apple은 4월 28일부터 Xcode 26·iOS 26 SDK를, Google Play는 8월 31일부터 Android 16(API 36) 타깃을 요구합니다. 무엇을 확인하고 어떻게 대응하는지 정리했습니다.

한동안 업데이트를 하지 않던 앱에 수정 사항이 생겨 빌드를 올렸는데 업로드 단계에서 막히는 일이 올해 들어 늘었습니다. 2026년에 두 스토어가 모두 제출 요건을 올렸기 때문입니다.

두 가지 변경 사항

스토어 시행일 요구 사항
App Store 2026년 4월 28일 Xcode 26 이상에서 iOS 26 SDK로 빌드
Google Play 2026년 8월 31일 신규 앱과 업데이트는 Android 16(API 레벨 36) 타깃

두 건 모두 이미 시행되었습니다. 지금 시점에서 오래된 환경으로 빌드한 결과물은 업로드되지 않습니다.

App Store — Xcode 26과 iOS 26 SDK

2026년 4월 28일부터 App Store Connect에 올리는 iOS·iPadOS 앱은 Xcode 26 이상에서 iOS 26 SDK로 빌드해야 합니다. 같은 규칙이 tvOS·watchOS·visionOS에도 적용됩니다.

이전에는 경고로만 표시되던 항목이라 그냥 넘어가신 분들이 많습니다. 그 경고가 아래 코드입니다.

ITMS-90725: SDK version issue.
This app was built with the iOS 18.x SDK.
Starting April 28, 2026, all iOS apps must be built with the iOS 26 SDK or later.

지금은 경고가 아니라 거부 사유입니다.

자주 오해하는 지점

SDK 버전과 지원 기기 버전은 다릅니다. iOS 26 SDK로 빌드하라는 것은 "무엇으로 만드느냐"의 문제이고, 어떤 OS 버전의 기기를 지원할지는 별개로 정합니다. Deployment Target을 iOS 15로 두면 iOS 15 기기에서도 그대로 동작합니다. 기존 사용자를 잃는 변경이 아닙니다.

확인 방법

Xcode에서 확인하실 항목입니다.

  1. Xcode 버전이 26 이상인지 (Xcode → About Xcode)
  2. macOS 버전이 그 Xcode를 지원하는지 — 여기서 막히는 경우가 가장 많습니다. Xcode 26을 설치하려면 macOS도 함께 올려야 하는 경우가 있습니다
  3. CI에서 빌드한다면 러너의 Xcode 이미지 버전

크로스플랫폼 프레임워크를 쓰는 경우

Flutter, React Native, Expo로 만든 앱도 결국 Xcode로 빌드하므로 같은 규칙을 받습니다. 다만 프레임워크나 플러그인이 새 SDK에서 컴파일되지 않는 경우가 있어 작업이 더 붙습니다.

상황 필요한 작업
프레임워크 버전이 최신에 가까움 Xcode 업데이트 후 재빌드로 대부분 해결
버전이 1~2년 뒤처짐 프레임워크 업그레이드 필요. 의존 패키지가 함께 깨지는 경우가 많음
Expo SDK 53 이하 SDK 업그레이드가 선행되어야 함
유지보수가 끊긴 네이티브 플러그인 사용 대체 라이브러리를 찾거나 직접 수정해야 함

세 번째와 네 번째에 해당하면 "빌드만 다시 하면 되는 일" 이 아닙니다. 의존성이 연쇄적으로 걸려 며칠에서 몇 주가 걸립니다.

Google Play — Android 16(API 36) 타깃

2026년 8월 31일부터 Google Play에 올리는 신규 앱과 업데이트는 targetSdkVersion 을 36 이상으로 맞춰야 합니다. 며칠 전에 시행되었습니다.

기기 종류에 따라 기준이 다릅니다.

대상 요구 타깃 API
일반 휴대폰·태블릿 앱 (신규·업데이트) 36 (Android 16)
Wear OS, Android Automotive OS 35 이상
Android TV, Android XR 34 이상

업데이트를 안 해도 되는 앱은 어떻게 되나

이미 올라가 있는 앱이 즉시 내려가지는 않습니다. 다만 타깃 API가 낮으면 새 사용자에게 노출되지 않습니다. API 34 이하를 타깃으로 하는 앱은 앱의 타깃보다 높은 Android 버전이 깔린 기기에서 설치되지 않습니다. 기존 설치 사용자는 계속 쓸 수 있지만 신규 유입이 막힙니다.

기한을 맞추기 어려운 사정이 있으면 Play Console에서 2026년 11월 1일까지 연장을 신청할 수 있습니다.

타깃 API를 올릴 때 실제로 부딪히는 것들

targetSdkVersion 숫자만 바꾸면 되는 일이 아닙니다. 타깃을 올리면 그 버전의 동작 변경이 앱에 적용되기 때문입니다. 최근 버전에서 자주 문제가 되는 지점입니다.

  • 사진·동영상 접근 권한 — 전체 접근 대신 선택한 항목만 허용하는 방식이 기본이 되어, 갤러리를 직접 훑던 코드가 동작하지 않습니다
  • 백그라운드 실행 제한 — 포그라운드 서비스 유형을 명시해야 하고, 유형에 맞는 권한 선언이 없으면 실행 시점에 예외가 발생합니다
  • 정확한 알람 — 정해진 시각에 알림을 띄우는 기능에 별도 권한이 필요합니다
  • 엣지 투 엣지 화면 — 상태 표시줄과 내비게이션 바 영역까지 화면이 확장되어, 대응하지 않으면 버튼이 시스템 바에 가립니다

마지막 항목은 기능이 아니라 화면 문제라 테스트에서 놓치기 쉽습니다. 실제 기기에서 화면 하단을 반드시 확인하십시오.

지금 확인하실 순서

운영 중인 앱이 있으시다면 아래 순서로 점검해 보십시오.

  1. 마지막 빌드 시점을 확인합니다. 2026년 4월 이전에 만든 iOS 빌드라면 다음 업데이트에서 반드시 막힙니다
  2. targetSdkVersion 값을 확인합니다. build.gradle 에 적혀 있습니다. 36 미만이면 신규 사용자 유입이 이미 제한되고 있습니다
  3. 빌드 환경을 실제로 돌려 봅니다. 요건 충족 여부는 문서로 판단할 수 없고, 빌드를 한 번 해 봐야 어디서 깨지는지 나옵니다
  4. 의존 패키지 상태를 봅니다. 유지보수가 멈춘 라이브러리가 있으면 그것이 병목이 됩니다

급하지 않아도 미뤄서 좋을 것이 없습니다

두 요건 모두 매년 올라갑니다. 한 해를 건너뛰면 다음에는 두 단계를 한꺼번에 올려야 하고, 그 사이 쌓인 의존성 문제까지 함께 처리해야 합니다. 지금 하루 걸릴 일이 내년에는 일주일이 되는 구조입니다.

대응이 막히셨다면

빌드가 깨지는 지점은 앱마다 다릅니다. 프레임워크 버전, 사용 중인 플러그인, 네이티브 코드 유무에 따라 반나절이면 끝나기도 하고 몇 주가 걸리기도 합니다.

저희 회사는 이런 스토어 요건 대응과 프레임워크 업그레이드 작업을 맡고 있습니다. 지금 앱이 어떤 상태인지 알려주시면 얼마나 걸릴 일인지부터 확인해 드리겠습니다. 문의 페이지로 남겨 주시면 됩니다.
